# Seven Segment
Seven Segments is an output device, that the MCU can control, The MCU can interface with it to output a number between $0$ and $9$, yyou can place multiple seven segments to display a number of multiple decimal places. 
It has many applications, like elevators, traffic light, digital clocks, ... 

It's workinfg idea is simple, it is literally composed of 7 segments arrayed together that can form any number. Your job is to set some of them and clear some of them so you get the shape of your number. 

![7 segments labeled by chars + dot placeholder](/Interfacing/Attachments/seven-segments-labeled-by-chars.png)

Segments are named $a$, $b$, $c$, $d$, $e$, $f$ and $g$. It also has a dot placed to low right, this dot is used to indicate a decimal fraction if you need it. 
Each segment is a led. Each Seven segments has 10 outer pins to interface with MCU. 

Seven Segments has two types (Common Anode and Common Cathode) , each of them has a different way of interfacing (different code and different connection). 

![Pinout diagram of a seven-segment display, showing the segment labels a through g, the decimal-point segment, and the external pins used to connect the display. The diagram provides a technical reference for wiring the display to a microcontroller; it has no emotional tone.](/Interfacing/Attachments/seven-segments-pinout.png)

## Common Cathode:
Internal Leds' Cathodes are all connected together into one electrical node, and connected into 2 outer pins, but the anode of each led is connected to a separate pin (8 pins) (7 segments + 1 dot). 

(altough cathode is 2 pins, they are the same electrical node, if you tested it with avometer on diode mode you will get short, they are made 2 pins to ease connectivity). 


## Common Anode
It resembles the common cathode, all the anode terminals of all leds are connected together into one electrical node, and connected into 2 outer pins, but the cathode of each led is connected to a separate pin (8 pins) (7 segments + 1 dot)

## Connection:
If we will use a common cathode seven segment, we now should connect the common pin with $GND$, the leds we want to lighten to $V_{CC}$, otherwise to $GND$.

If we want to display number 1 we should turn on segments $b$ and $c$.

---

If we will use a common anode seven segment, we now should connect the common pin with $V_{CC}$, The leds we want to lighten to $GND$, otherwise to $V_{CC}$.

---

## How to know its type and its pinout?
You can look for its name on the chip and search about that name's datasheet.

What if internet has vanished and we are at an apocalypse, there is no datasheets and there is no water or oxygen?

We can check it using avometer.

If you put the avometer on the diode mode (short detector mode) on the terminals of a led where the V part is facing diode's anode and the common part is facing the diode's cathode, you will find the led is lighting, and the avometer displays the $V_{gamma}$ of the led, if didn't lighten? then you need to switch poles.

You can put the avometer in diode mode (short detector mode) and connect comm pin of avo on the *com* pin of the seven segments, and the other pin connect it to any of the other seven segment's pins, if it lights then it is common cathode, if we need switching poles then it is common anode.

### Basic Software
Finally something interesting.

Imagine we want to display numbers from 0 to 9 then the dot then repeats with a delay 1s between each.  

We are writing basic code without autosar architecture.

If we are inside the main, what would we do first?
- Initially we will define the port as an output. 
```c
int main(void) {
    DDRA = 0xff; // All output
}
```

- Then we want to display numbers from 0 to . with delay.
```c
int main(void) {
    DDRA = 0b11111111;

    while(1) {
        PORTA = 0b00111111;  // 0
        _delay_ms(1000);

        PORTA = 0b00000110; // 1
        _delay_ms(1000);

        PORTA = 0b01011011; // 2
        _delay_ms(1000);

        PORTA = 0b01001111; // 3
        _delay_ms(1000);

        PORTA = 0b01100110; // 4
        _delay_ms(1000);

        PORTA = 0b01101101; // 5
        _delay_ms(1000);

        PORTA = 0b01111101; // 6
        _delay_ms(1000);

        PORTA = 0b00000111; // 7
        _delay_ms(1000);

        PORTA = 0b01111111; // 8
        _delay_ms(1000);

        PORTA = 0b01101111; // 9
        _delay_ms(1000);

        PORTA = 0b10000000; // .
        _delay_ms(1000);
    }
}
```
 
This code is fine and it works, but it's incosistent and hard to use.

A better approach is to put all this codes in an array of 11 places, (10 numbers and dot), and then I keep looping on the array.

```c
int main(void) {

    uint8_t arr[11] = { 
        0b00111111, // 0
        0b00000110, // 1
        0b01011011, // 2
        0b01001111, // 3
        0b01100110, // 4
        0b01101101, // 5
        0b01111101, // 6
        0b00000111, // 7
        0b01111111, // 8
        0b01101111, // 9
        0b10000000  // .
    };

    DDRA = 0b11111111;
    uint8_t counter = 0;
    
    while(1) {
        PORTA = arr[(counter++)%11];

        _delay_ms(1000);  
    }
}
```

I am here looping on the array with a counter that starts at 0 and keeps increasing it and keeping the range inside the subscriptor operator between 0 and 11.
A problem that may appear in this code is that when the counter overflows (resets to zero), it overflows on 256 which is not a multiple of 11. It resets to zero at 3 instead of at 11.
To solve this we need to keep the boundings of the counter itself between 0 and 11, instead of keeping the boundings of the subscriptor operator range.

This can be done by two ways: 
- Reset it manually:
```c
while(1) {
    PORTA = arr[counter];

    if(counter == 11) {
        counter = 0;
    }

    _delay_ms(1000);
}

Assinging new value to the counter:
```c
while(1) {
    PORTA = arr[counter];

    counter = (counter+1) % 11;

    _delay_ms(1000);
}
```

You can leave the idea of counters and simply do a for loop inside the while loop:
```c
while(1) {
    for(uint8_t i = 0; i<12; i++) {
        PORTA = arr[i];
        _delay_ms(1000);
    }
}
```


If we want to connect MCU into common anode seven segments, we need to invert all this codes using bitwise not, like this:

```c
while(1) {
    for(uint8_t i = 0; i<12; i++) {
        PORTA = ~arr[i];
        _delay_ms(1000);
    }
}
```

We can display from 0 to 15 using hexadecimal numbering system also:

```c
int main(void) {

    uint8_t arr[17] = { 
        0b00111111, // 0
        0b00000110, // 1
        0b01011011, // 2
        0b01001111, // 3
        0b01100110, // 4
        0b01101101, // 5
        0b01111101, // 6
        0b00000111, // 7
        0b01111111, // 8
        0b01101111, // 9
        0b01110111, // 10 -> A
        0b01111100, // 11 -> b
        0b00111001, // 12 -> C
        0b01011110, // 13 -> d
        0b01111001, // 14 -> E
        0b01110001, // 15 -> F
        0b10000000  // .
    };

    DDRA = 0b11111111;
    uint8_t counter = 0;
    
    while(1) {
        for(uint8_t i = 0; i<17; i++) {
        PORTA = arr[i];
        _delay_ms(1000);
    }
    }
}
```

### Seven Segments Driver
We need to make a driver for the seven segments, following the autosar architecture we will find that the `seven_segments.c` and `seven_segments.h` belong to the HAL as they are external hardware outside the MCU.

We will make a header file first:
```c
#ifndef SEVEN_SEGMENT_H
#define SEVEN_SEGMENT_H

#include "../MCAL/Dio.h"

void Seven_seg_Init(uint8_t port);
void Seven_seg_Write(uint8_t port, uint8_t displayValue, uint8_t isCommonCathode);

#endif
```

Then we will create a source file (`seven_segment.c`) where we will first include our header file:

```c
#include "seven_segment.h"
```

Then our first function:

#### `void Seven_seg_Init(uint8_t port)`
This function is for defining the seven segment as an output, normally you can connect the seven segment to different ports, you can connect it to from $PA4$ to $PA7$ and from $PD0$ to $PD4$, but this function won't work so it is not recommneded, you have to connect the pins of the seven segment to an accurate order to only 1 port.

```c
void Seven_seg_Init(uint8_t port) {
    Dio_SetPortDirection(port, 0xff); 
    // Makes all port's pins an output.
}
```

### `void Seven_seg_Write(uint8_t port, uint8_t displayValue)`
This function writes a value to the seven segment.

```c
static const uint8_t sev_seg_map[17] = { 
    0b00111111, // 0
    0b00000110, // 1
    0b01011011, // 2
    0b01001111, // 3
    0b01100110, // 4
    0b01101101, // 5
    0b01111101, // 6
    0b00000111, // 7
    0b01111111, // 8
    0b01101111, // 9
    0b01110111, // 10 -> A
    0b01111100, // 11 -> b
    0b00111001, // 12 -> C
    0b01011110, // 13 -> d
    0b01111001, // 14 -> E
    0b01110001, // 15 -> F
    0b10000000  // .
};
        
void Seven_seg_Write(uint8_t port, uint8_t displayValue, uint8_t isCommonCathode) {
    if(displayValue < 17) {
        if(isCommonCathode) {
            Dio_WritePort(port, sev_seg_map[displayValue]);
        } else {
            Dio_WritePort(port, ~sev_seg_map[displayValue]);
        }
    }
}
```


#### Why `static`?
The array here is defined as `static` to be seen only in this file, as symbols by default are accessible to likage across different `.c` files, but `static` makes it for this `.c` file only it disables external linkage, only internal linkage will happen.

#### Why `const`?
`const` in normal general purpose programming just means that the compiler won't let you change anything in that variable.
While, in embedded systems programming we know much more about this.

##### Without `const`:

```c
uint8_t sev_seg_map[17] = { 
    0b00111111, // 0
    0b00000110, // 1
    0b01011011, // 2
    0b01001111, // 3
    0b01100110, // 4
    0b01101101, // 5
    0b01111101, // 6
    0b00000111, // 7
    0b01111111, // 8
    0b01101111, // 9
    0b01110111, // 10 -> A
    0b01111100, // 11 -> b
    0b00111001, // 12 -> C
    0b01011110, // 13 -> d
    0b01111001, // 14 -> E
    0b01110001, // 15 -> F
    0b10000000  // .
};
```

The compiler will save this map in the flash initially (at `flash/.data`) when we start the MCU, the startup code copies these 17 bytes from flash to RAM (from `flash/.data` to `RAM/.data`) which means we have consumed too much from flash and RAM.

##### With `const`:

```c
const uint8_t sev_seg_map[17] = { 
    0b00111111, // 0
    0b00000110, // 1
    0b01011011, // 2
    0b01001111, // 3
    0b01100110, // 4
    0b01101101, // 5
    0b01111101, // 6
    0b00000111, // 7
    0b01111111, // 8
    0b01101111, // 9
    0b01110111, // 10 -> A
    0b01111100, // 11 -> b
    0b00111001, // 12 -> C
    0b01011110, // 13 -> d
    0b01111001, // 14 -> E
    0b01110001, // 15 -> F
    0b10000000  // .
};
```

The compiler now will store them in flash only with no copies (`flash/.rodata`).

We finally add a boundary checking rejecting anything greater than 17, where 15 is `F` and 16 is `.`.

We can use it in main like this:

```c
#define F_CPU 8000000UL
#include "myUtils/HAL/Seven_Segment.h"
#include <util/delay.h>

int main(void) {

    Seven_seg_Init('A');    

    while(1) {
        for(uint8_t i = 0; i<17; i++) {
            Seven_seg_Write('a', i, 1);
            _delay_ms(1000);
        }
    }
}
```

## Examples

### From 0 to 9

Imagine we want to make a project where initially the seven segment displays zero and if we press on a push button it increases the number displayed till we counter 9, if we press again it resets to zero.

##### Connection:

![placeholder](/Interfacing/Attachments/button+seven-segments-connection-protues.png)

We have connected common cathode seven segments into port "D" and a pull down push button to "PD0".

##### Software:

```c
#define F_CPU 8000000UL
#include "myUtils/HAL/Seven_Segment.h"
#include "myUtils/HAL/Button.h"
#include <util/delay.h>

int main(void) {

    Button_Init('D', 0, 0);
    Seven_seg_Init('A');
    
    uint8_t counter = 0;
    Seven_seg_Write('A', counter, 1); // Initially displaying zero with no need to press

    while(1) {
        if(Button_ReadState('D', 0)) {
            _delay_ms(30);

            if(Button_ReadState('D', 0)) {
                Seven_seg_Write('A', counter, 1);
                counter = (counter + 1) % 10;
                
                while(Button_ReadState('D', 0));

            }
        }
    }
}
```

We here created a 2 stage button checking known as *Software Debouncing*.

If the button is pressed then the seven segment displays a value of `i`, `i` is initially set to `0`, then with each press we increment the counter with keeping its value from 0 to 9.

The while loop at the end is to solve the problem of blocking till release.

# BCD Interfacing

There is a real problem in interfacing with seven segment. To interface with only 1 seven segment you need a whole port, you need 8 pins.

To solve this problem we use BCD, where you can interface with the seven segment with only 4 pins.

![Block diagram showing a microcontroller connected to a BCD-to-seven-segment decoder through four signal lines; the decoder converts the binary-coded decimal input into the segment signals needed to drive a seven-segment display.]( /Interfacing/Attachments/bcd.png)

You connect the BCD to Seven Segment Decoder to only 4 MCU pins and it outputs the 8 pins needed to the seven segment.

Each Type of Seven Segment has its decoder type (Common Anode BCD Decoder or Common Cathode BCD Decoder).

## Connection
Let's talk about the Common Cathode BCD Decoder.

The decoder accepts 4 inputs from you, if you output `0000` to it, it will decode it into the code that makes the common cathode seven segment lights `0` which is `0b00111111`, and if you output `0001` to it, it will decode into the code equivalent to `1` which is `0b00000110`, and so on.

![Truth table for a BCD-to-seven-segment decoder, listing four-bit binary-coded decimal inputs and the corresponding seven-segment outputs for displaying decimal digits. The table is presented as a technical reference diagram in the surrounding electronics documentation.]( /Interfacing/Attachments/bcd-truth-table.png)

### Software
Now we need to make a new driver that can interface with this bcd decoder.

The new driver should write on only 4 pins of the port that the bcd decoder is connected to.

Normally the decoder is connected into the lower nibble of the port.

If we are using port "A", then the Bcd should be connected into $PA0$, $PA1$, $PA2$ and $PA3$ in case of lower nibble, and $PA4$, $PA5$, $PA6$ and $PA7$ in case of higher nibble.

> Note: A limitation of this approach is you can not connect your BCD to pins that are in between nibbles.

We will make a header file first:
```c
#ifndef SEVEN_SEGMENT_BCD_H
#define SEVEN_SEGMENT_BCD_H

#include "../MCAL/Dio.h"

void Seven_seg_Bcd_Init(uint8_t port);

#endif
```

Second we will make the source file:
```c
#include "Seven_Segment_BCD.h"
```

#### `void Seven_seg_Bcd_Init(uint8_t port, uint8_t is_lowerNibble)`

This function initializes the pins connected to the BCD by setting them as output pins.
It has a boolean named `is_lowerNibble` that indicates wether we connected the BCD to the lower nibble or the higher nibble of the port.

```c
void Seven_seg_Bcd_Init(uint8_t port, uint8_t is_lowerNibble) {
    if(is_lowerNibble) {
        Dio_SetPinDirection(port, 0, 1);
        Dio_SetPinDirection(port, 1, 1);
        Dio_SetPinDirection(port, 2, 1);
        Dio_SetPinDirection(port, 3, 1);
    } else {
        Dio_SetPinDirection(port, 4, 1);
        Dio_SetPinDirection(port, 5, 1);
        Dio_SetPinDirection(port, 6, 1);
        Dio_SetPinDirection(port, 7, 1);
    }
}
```

#### `void Seven_seg_Bcd_Init(uint8_t port, uint8_t is_lowerNibble, uint8_t displayValue)`

This function takes the number you want to send and encode into binary coded decimal.

```c
void Seven_seg_Bcd_Write(uint8_t port, uint8_t is_lowerNibble, uint8_t displayValue) {
    is_lowerNibble ? Dio_WriteLowerNibble(port, displayValue) : Dio_WriteHgiherNibble(port, displayValue);
}
```

Now we need to implement both of `Dio_WriteLowerNibble()` and `Dio_WriteHigherNibble()`:

Inside the `Dio.h` we will add them:

```c
// Nibble Functions
void Dio_WriteLowerNibble(uint8_t port, uint8_t value);
void Dio_WriteHigherNibble(uint8_t port, uint8_t value);
```

and inside the `Dio.c` we will add thier implementation:

We know that the lower nibble is from pin 0 to pin 3 while the hgiher nibble is from 4 to 7, so we know that we will call `Dio_WritePin()` 4 times in each function with changing the `pinNum` in each.

```c
// Nibble Functions
void Dio_WriteLowerNibble(uint8_t port, uint8_t value) {
    Dio_WritePin(port, 0, );
    Dio_WritePin(port, 1, );
    Dio_WritePin(port, 2, );
    Dio_WritePin(port, 3, );
}

void Dio_WriteHigherNibble(uint8_t port, uint8_t value) {
    Dio_WritePin(port, 4, );
    Dio_WritePin(port, 5, );
    Dio_WritePin(port, 6, );
    Dio_WritePin(port, 7, );
}
```

Now we need to think a little bit about how to encode the decimal `value` into a binary coded decimal `value` and send each bit to each `Dio_WritePin()` where the first `Dio_WritePin()` should receive the first bit (LSB) of binary coded decimal `value` and the second `Dio_WritePin()` should receive the second bit of binary coded decimal `value` and so on.

```c
// Nibble Functions
void Dio_WriteLowerNibble(uint8_t port, uint8_t value) {
    Dio_WritePin(port, 0, READ_BIT(value, 0));
    Dio_WritePin(port, 1, READ_BIT(value, 1));
    Dio_WritePin(port, 2, READ_BIT(value, 2));
    Dio_WritePin(port, 3, READ_BIT(value, 3));
}

void Dio_WriteHigherNibble(uint8_t port, uint8_t value) {
    Dio_WritePin(port, 4, READ_BIT(value, 0));
    Dio_WritePin(port, 5, READ_BIT(value, 1));
    Dio_WritePin(port, 6, READ_BIT(value, 2));
    Dio_WritePin(port, 7, READ_BIT(value, 3));
}
```

We used here the macro like a function named `READ_BIT()` that will encode the `value` and return the bit associated to read.

If the value is `6` which means `0000 0110` it will be expanded like this:
```c
Dio_WritePin(port, 0, 0);
Dio_WritePin(port, 1, 1);
Dio_WritePin(port, 2, 1);
Dio_WritePin(port, 3, 0);
```

which is what we want exactly.

#### Software V2.0

There is another way to make the two functions of the `Dio_WriteLowerNibble()` and `Dio_WriteHigherNibble()` which is bitmasking.

##### Lower Nibble

If we are connecting the BCD 7 Segment Decoder into the lower nibble of Port "A", you can notice
that initially we have some data on *PORTA* register, we want to write on pins *PA0*, *PA1*, *PA2* and *PA3* which are controlled using the least significant 4 bits in *PORTA*.

So, we can take the least significant 4 bits of the `value` variable and put them as they are on the least significant 4 bits in *PORTA* register.

![placeholder](/Interfacing/Attachments/bcd-bitmasking.png)

We here have the value we want to write is 7 which is `0000 0111` in binary, what we want to do is to take the Least Significant 4 bits in `value` and put them as they are in the Least Significant 4 bits - LS4B - in *PORTA* with keeping its Most Significat 4 bits - MS4B - safe.

So, we can use bitmasking to do this.

We can first clear the LS4B of *PORTA* register, then set them to the values of `value`.

This can be done like this:
```c
// Imagine `value` was 7 (0000 0111).

    PORTA &= 0b11110000;    // or 0xf0
    /*
        If PORTA was:               0101 0101
        and anded with:             1111 0000
        -------------------------------------
        It will be:                 0101 0000
        
        As we cleared the LS4B and Kept the MS4B
    */
    
    PORTA |= value;
    /*
        If value was 7:             0000 0111
        and PORTA was:              0101 0000
        -------------------------------------
        It will be:                 0101 0111
    */
```

But there is a small problem, the user may enter a number greater than $2^4 - 1$ (15) which will change in the MS4B, so we need to make sure that the number stays under 16.

> It doesn't mean anything that a user enters value greater than 9, but we are doing this for safety (Not to lose the data inside *PORTA*)

```c
// Imagine `value` was 35 (0010 0011).

    PORTA &= 0b11110000;    // or 0xf0
    /*
        If PORTA was:               0101 0101
        and anded with:             1111 0000
        -------------------------------------
        It will be:                 0101 0000
        
        As we cleared the LS4B and Kept the MS4B
    */
    
    PORTA |= value;
    /*
        If value was 35:            0010 0011
        and PORTA was:              0101 0000
        -------------------------------------
        It will be:                 0111 0011
                                      ^      
                    You have disrubted your *PORTA* register.
    */
```

So for safety we tend to keep the `value` entered by user under 16, so that its MS4B stays zeros.

This can be done by first clearing all the MS4B of `value`.

```c
// Imagine `value` was 35 (0010 0011).

    value &= 0b00001111;    // or 0x0f
    /*
        if value was 35:            0010 0011
        and anded with:             0000 1111
        -------------------------------------
        It will be:                 0000 0011

        As we cleared the MS4B and Kept the LS4B.
    */

    PORTA &= 0b11110000;    // or 0xf0
    /*
        If PORTA was:               0101 0101
        and anded with:             1111 0000
        -------------------------------------
        It will be:                 0101 0000
        
        As we cleared the LS4B and Kept the MS4B.
    */
    
    PORTA |= value;
    /*
        value now is:               0000 0011
        and PORTA was:              0101 0000
        -------------------------------------
        PORTA will be:              0101 0011

        Kept safe.
    */
```

Now, we can do the same for all ports using a `switch` case:

```c
void Dio_WriteLowerNibble(uint8_t port, uint8_t value) {
    value &= 0x0f;

    switch(port) {
        case 'A':
        case 'a':
            PORTA &= 0xf0;
            PORTA |= value;
            break;

        case 'B':
        case 'b':
            PORTB &= 0xf0;
            PORTB |= value;
            break;

        case 'C':
        case 'c':
            PORTC &= 0xf0;
            PORTC |= value;
            break;

        case 'D':
        case 'd':
            PORTD &= 0xf0;
            PORTD |= value;
            break;

        default:
            break;
    }
}
```

That's juicy tbh.

##### Higher Nibble

We want to do the same but with the higher nibble, 

If we are connecting the BCD 7 Segment Decoder into the higher nibble of Port "A", you can notice that initially we have some data on *PORTA* register, we want to write on pins *PA4*, *PA5*, *PA6*, and *PA7* which are controlled using the most significant 4 bits in *PORTA*.

So, we can take the least significant 4 bits of the `value` variable and put them as they are on the most significatnt 4 bits in *PORTA* register.

![placeholder](/Interfacing/Attachments/bcd-bitmasking-higher-nibble.png)

We here have the value we want to write is 7 which is `0000 0111` in binary, what we want to do is to take the Least Significant 4 bits in `value` and put them as they are in the Most Significant 4 bits - MS4B - in *PORTA* with keeping its Least Significat 4 bits - LS4B - safe.

So, we can use bitmasking to do this.

We want the LS4B of `value` to be in correct place to bitmask it with *PORTA*'s MS4B, we can do this by left shifting `value` by 4 steps.

```c
value <<= 4;
```

After this we need to clear the MS4B of *PORTA* to prepare it for bitmasking with `value`.

```c
PORTA &= 0b00001111; // or 0x0f
```

Then we can or them together.

```c
PORTA |= value;
```

So, the final will be like this:

```c
// Imagine `value` was 7 (0000 0111).

    value <<= 4;    
    /*
        If value was 7:             0000 0111
        -------------------------------------
        It will be:                 0111 0000
    */

    PORTA &= 0b00001111;    // or 0x0f
    /*
        If PORTA was:               0101 0101
        and anded with:             0000 1111
        -------------------------------------
        It will be:                 0000 0101
        
        As we cleared the MS4B and Kept the LS4B.
    */
    
    PORTA |= value;
    /*
        value now is:               0111 0000
        and PORTA was:              0000 0101
        -------------------------------------
        PORTA will be:              0111 0101

        Kept safe.
    */
```

Now, we can do the same for all ports using a `switch` case:

```c
void Dio_WriteHigherNibble(uint8_t port, uint8_t value) {
    value <<= 4;

    switch (port)
    {
        case 'A':
        case 'a':
            PORTA &= 0x0f;
            PORTA |= value;
            break;
        
        case 'B':
        case 'b':
            PORTB &= 0x0f;
            PORTB |= value;
            break;

        case 'C':
        case 'c':
            PORTC &= 0x0f;
            PORTC |= value;
            break;

        case 'D':
        case 'd':
            PORTD &= 0x0f;
            PORTD |= value;
            break;

        default:
            break;
    }
}
```
